# Jev-X v1.2: Research Layer (LuxAlgo review)

Reviewed 2026-09-25. Decision: adopt PineTS as the research-layer engine for
v1.2, with the licensing boundary and sequencing described below.

## Gaps in v1.1 (market-brief/jev_analyze.py)

1. **Funding rate is estimated, not real** (`jev_analyze.py:465`):
   `funding = 0.010 if change_24h > 3 else (-0.015 if change_24h < -3 else 0.005)`.
   The squeeze-risk question depends on this input, so it is the weakest link
   in the decision state.
2. **Stocks/ETFs get no technicals** (`jev_analyze.py:931-932`): RSI fixed at
   50.0, funding at 0.0 for SMH, DRAM, COIN, HOOD, BE. Jev sees no momentum
   context for stocks.
3. **Fixed-% trade levels** (`build_levels`, `jev_analyze.py:699`): stops at
   -3.8% / targets at +4.5% / +8.5% for every asset regardless of volatility
   or structure. A 3.8% stop is noise on HYPE and a canyon on BTC.

## Recommended indicator set (keep to 3-5 features)

ATR(14), Supertrend trend direction, Chaikin Money Flow(20), break-of-structure
flags on confirmed pivots, swing high/low for structure targets. Add each only
if the v1.1 hit-rate log shows it improves decisions. Per the 2026-08-28
backtest: mechanical indicator rules failed after costs; CMF had real
discriminative power. **Indicators feed Jev as context, never as standalone
signals.**

## What LuxAlgo does NOT fix

**Real funding rates (gap #1) are outside the LuxAlgo set.** This gets its own
workstream: Binance `/fapi/v1/fundingRate` (public, keyless) for BTC/ETH/SOL/
NEAR, Hyperliquid public info endpoint for HYPE funding. Keep the current
estimate as fallback. This is v1.2b, not "later" — squeeze-risk is the question
that needs it.

## Licensing boundaries (read research/README.md)

- PineTS/pinets-cli are AGPL-3.0. The Python side must call them as a **separate
  process** (`.pine` in, JSON out over stdout) — no `import pinets` in shipped
  code; that is linking and would AGPL the importing file.
- LuxAlgo Library scripts are CC BY-NC-SA 4.0. **Do not copy their Pine source
  into this repo.** Reimplement standard SMC concepts (BOS/CHoCH, FVG, order
  blocks) from first principles — ideas aren't copyrightable, their code is.
- MIT/CC0 repos (edge-stats, market-trackers, mcp-server) are fine to use freely.

## PoC (validated 2026-09-25)

`research/research.pine` (Pine v6: ATR, Supertrend, confirmed 5/5 pivots, BOS,
CMF) ran under PineTS 0.9.34 on OHLCV JSON and returned latest plot values as
JSON. Cautions carried forward:

- Closed bars only. SMC/pivot scripts confirm late and can repaint — never read
  the forming bar.
- `bars.slice(0, -1)`-style drops must be **timeframe-aware**: Kraken's OHLC
  last candle is the incomplete interval (drop it); Stooq daily stock bars are
  closed sessions (do NOT drop).
- Daily pivots 5/5 confirm ~5 bars late. For the twice-daily crypto cadence,
  prefer 4h bars (Kraken `interval=240`, keyless); daily is fine for stocks.
- Verify the Supertrend direction sign convention against actual PineTS output
  before Jev reads it as trend — a sign error inverts the feature silently.
- BOS on confirmed pivots can whipsaw in ranges; it is a context flag, not a vote.

## Sequencing

- **v1.2a (core):** pinets-cli subprocess → research JSON (ATR, RSI-14 for
  stocks, Supertrend dir, CMF-20, BOS flags, swing high/low) → `build_levels()`
  rebuilt as stop = 1.5×ATR, T1 = 1.5R, T2 = structure (swing high/low) or 3R.
  The same Pine run yields both ATR and structure targets.
- **v1.2b:** real funding rates (Binance + Hyperliquid, keyless) → fixes the
  squeeze-risk input.
- **v1.2c:** edge-stats calibration on the v1.1 prediction-vs-outcome log.
- **Later:** market-trackers for stocks; trade-journal when live.
